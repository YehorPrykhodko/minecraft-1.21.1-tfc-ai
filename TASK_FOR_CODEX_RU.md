# Задача Codex: переписать TFC Wildlife AI Remaster с нуля

## Контекст
Существующий пользовательский мод `tfc_wildlife_ai` версии 2.0.0-alpha3.24 содержит поведение животных для TerraFirmaCraft. Он работает, но сформировался из последовательных модификаций JAR. Несколько независимых блоков (`TFCWildlifeAI`, `Alpha34Runtime`, `SpeciesBehavior2026`, а также дополнительные Guards) могут по очереди переопределять намерения и задачи навигации. Это создаёт рывки, внезапные развороты, кратковременные прерывания погони и логические противоречия.

Требуется **новый сопровождаемый проект Java + Gradle + NeoForge**, а не очередной патч старого байт-кода. Не терять нужные механики, однако не повторять старую внутреннюю архитектуру.

## Первое действие
1. Прочитать `AGENTS.md`, `docs/BEHAVIOR_SPEC_RU.md`, `docs/ARCHITECTURE.md`, `docs/REPRODUCTIONS.md` и `tests/acceptance_cases.json`.
2. Проинспектировать `legacy/wildlife-ai-324.jar` (и при необходимости предыдущие JAR) через `javap` или декомпилятор. Составить инвентаризацию существующего поведения, точек интеграции с TFC/TaCZ и классов Mixin.
3. Написать `docs/AUDIT.md`: что установлено точно, что предполагается, что требует проверки в игре. По умолчанию не считать произвольные числовые константы из старого мода правильным балансом.
4. Создать готовую структуру Gradle для NeoForge 1.21.1 и Java 21. Переиспользовать mod id `tfc_wildlife_ai` и совместимый пакет/сохранение NBT там, где это необходимо.
5. Реализовать чистый, детерминированно тестируемый доменный слой: PerceptionSnapshot → species proposals → priority/hysteresis reducer → CommittedDecision → NavigationExecutor → Debug trace. Дать одному модулю право окончательно менять состояние и маршрут.
6. Начать с гризли и гиен; потом переносить остальные виды по аудиту. Не добавлять неподтверждённую механику только ради полноты.
7. Настроить нормальную диагностику, по которой можно восстановить цепочку: событие → предложение → решение → навигация → результат.
8. Написать и запускать автоматические тесты; собрать JAR через Gradle, зафиксировать результаты и ограничение игровой проверки.

## Критерии поведения
### Медведи, особенно гризли
- Медведь может сначала насторожиться, угрожать или отойти при появлении игрока: осторожная реакция допустима.
- Если он уже **решил напасть/защищаться агрессивно**, обычное сближение, собственное обнаружение игрока, небольшое изменение pursuit-score и отсутствие нового опасного события НЕ должны разрывать атаку на один тик. `ATTACK↔DEFEND↔RETREAT` каждые 40–100 мс — регрессия.
- Реальный испуг (`FLEE`) и осторожное отступление (`RETREAT`) отличать концептуально. При серьёзном ранении, действительной угрозе или достаточно сильной реакции на выстрел побег должен оставаться возможным.
- Маршрут отступления нельзя перегенерировать каждый тик, если цель ещё валидна; навигация должна иметь hysteresis/stuck detection.
- Совместимость с TFC v18: существующая сглаженная анимация походки медведя, повышенные скорости, без скачков или тряски. Конкретные множители сверить с существующим кодом и требованиями; не переносить слепо.

### Гиены
- **Стая** (минимум 2 подходящие взрослые гиены): для *неспровоцированного нападения на игрока* используется доля HP игрока. В alpha3.23 использовался ориентир ниже 70% максимума; сохранить как конфигурируемый стартовый порог до уточнения. Голод конкретной гиены не должен автоматически начинать массовую атаку стаи. Самооборона от прямого урона остаётся.
- Решение атаковать ослабленного игрока должно координироваться внутри реально определённой стаи, без сценария, где половина группы переходит в `ATTACK`, а остальные без причины остаются `DEFEND`.
- **Одиночная** гиена: не начинает охоту на игрока, если не голодна. При сильном голоде нападение возможно, но должно быть редким/индивидуальным и детерминированно тестируемым; голод не означает автоматического нападения.
- Не смешивать голод с преследованием, тревогой, ранениями. Сильно раненная гиена не должна переходить `FLEE→HUNT` просто из-за голода.
- Стабилизировать подсчёт стаи и роли, чтобы при перемещении животных на секунду не происходило переключения SOLO↔PACK из-за колебаний радиуса поиска.

### Остальные виды / сохранение механик
После аудита восстановить зрение (в том числе LOS), слух (шаги/бег/прыжки/выстрелы), индивидуальные черты, сытость, усталость, осторожность, социальную реакцию, детёнышей и другие существующие механики, но только через единый механизм решения. Учесть старые пожелания: волки ускорены, медведи/медвежата имеют разные скорости преследования и бегства; пумы/пантеры делают краткую остановку, дистанцируются или устраивают засаду в зависимости от поведения игрока. Эти пункты требуют проверки исходного поведения и количественных коэффициентов.

## Не допускается
- Подменить чистую архитектуру ещё одним `IntentStabilityGuard` поверх старой системы.
- Дать нескольким независимым классам право напрямую записывать `intent`/`reason` или двигать `navigation.moveTo` без арбитража.
- Сделать гризли иммунным к любому страху вместо устранения ложных микропереключений.
- Отключить механику звуков выстрелов или TaCZ без явного объяснения и альтернативы.
- Использовать NBT-поля старой версии так, чтобы испортить сохранения; продумать миграцию или версионирование.
- Утверждать, что протестировано в Minecraft, если выполнены только сборка и тесты без запуска игры.

## Что вернуть по итогам работы
- Исходный код, конфигурацию Gradle, мод-интеграцию NeoForge, Mixin при необходимости, тесты и документацию.
- Воспроизводимый способ `gradlew build` с Java 21, и при успехе готовый `.jar`.
- Отчёт по старому и новому поведению; матрицу автоматических проверок; известные ограничения и инструкции по тестированию в игре.
- Специально проверить кейсы `grizzly#644` и ранние версии `#776`, `#1709` на логические инварианты.

При отсутствии необходимых библиотек или TFC v18 **сначала реализуй и протестируй независимую от Minecraft логику**, а затем честно сообщи, какую конкретно зависимость требуется добавить. Не останавливай весь проект из-за отсутствия готового файла.
