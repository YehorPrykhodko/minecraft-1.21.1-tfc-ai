# Совместимость и исходные бинарные материалы

## На что ориентироваться

- Minecraft `1.21.1`
- NeoForge `21.1.235`
- Java runtime `21`
- TerraFirmaCraft `4.2.7`, в игре используется модифицированный пользователем вариант `alt-rmb-v18-no-sleep-Z-snore19-complete`.
- TaCZ `1.1.8` (локальная сборка `hotfix-r3`).
- Старая реализация мода объявляет обязательные зависимости `tfc` `[4.2.6,4.3)` и `tacz` `[1.1.8,1.2)`.
- JAR может использовать не только стандартную версию TFC, но и изменения локального v18 (например, походка медведей, режим сна); требуется тестирование совместимости.

## Что внутри архива

`legacy/wildlife-ai-324.jar`, `legacy/wildlife-ai-323.jar`, `legacy/wildlife-ai-321.jar` — пользовательские JAR для анализа.

**Исходного Java-проекта нет**: классы/методы отражены в `docs/legacy_api.txt` по `javap -p`.

**Сам TFC v18 не включён в этот архив**, поскольку он большой (~63 МБ) и содержит сторонний мод. Пользователь может передать его отдельно как входные данные для тестовой совместимости. Не коммитить сторонний JAR в общедоступный репозиторий без проверки лицензии. Можно настроить получение разрешённых зависимостей через Maven, а локальный файл подключать в dev-окружении по пути, не находящемуся в Git.

## Правила логов

Журналы в `logs/` очищены до строчек `[TFC-WILDLIFE-*]`. Это **не полные игровые логи**, и они не заменяют диагностику крашей/загрузки. Исходные `latest.log` нужны для поиска совместимости и сбоев загрузки, но не требуются для анализа поведения.
