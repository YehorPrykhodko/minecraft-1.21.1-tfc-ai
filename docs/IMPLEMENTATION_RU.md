# Архитектура v4 и принятые решения

`core` не зависит от Minecraft. `mod` преобразует серверные наблюдения в immutable
Perception, координирует группы до индивидуального арбитража и исполняет результат.

`Memoire → Evaluation → MotifsEspece/MotifsPredateur → Arbitre → Navigation/Sons → Journal`.
Arbitre — единственный автор Decision (phase, motif, reason, target, since, lock).
Повторный вызов в одном тике возвращает тот же Resultat. Все предложения и veto
сохраняются; отклонённое предложение не выдаёт маршрут, звук и не меняет причину.
Чистый интерфейс MotifsEspece допускает профили PROIE/NEUTRE без изменений арбитра.
Реально управляются только 12 точных EntityType TFC; чужие/неподдержанные сущности
не получают чужой AI. Неизвестный Predator ID явно сообщается в журнале.

## Решения и движение

Фазы включают SLEEP, IDLE, WANDER, OBSERVE, ASSESS, WARN, HOLD_GROUND, DRIVE_OFF,
RETREAT, FLEE, TRACK, HUNT, ATTACK, REST, FOLLOW_PARENT. Мотив отдельно описывает
hunger, pack hunt, retaliation, offspring defense, defense, survival, family.
При прямом уроне и защите потомства предупреждение необязательно. Обычные предложения
не разрывают уже начатый бой; потеря цели, критическая опасность и непроходимый путь
с отдельной задержкой повторной попытки могут его прекратить.

Экстремальный голод преодолевает обычный страх; критическое здоровье/истощение,
огонь/лава/удушье и сильная паника остаются выше. После паники действует восстановление,
отсчитываемое и от последних принятых опасных событий. Гиены при >=2 обнаруженных
игроках прекращают мотив неспровоцированной охоты через HOLD_GROUND. Защита отдельна.
Для человеческой охоты стаи голод не является критерием; расчёт вероятности:
`clamp((fitAdults - 1) * packConfidenceWeight * (1 - playerHp), 0, packHuntChanceMax)`.
Нужны один подтверждённый игрок, минимум два способных взрослых и HP ниже
playerHpHuntThreshold. Один общий бросок сохраняется для пары группа/цель; он
не повторяется каждый тик. Числа — предложенная модель, не извлечённая формула 2.x.

Членство имеет радиусы входа/выхода и задержку распада. Исключения: cub, injured,
panic, path_blocked, assist_distance, target_unconfirmed. Общий защитный вызов
доступен здоровым близким участникам. Невидимые игроки имеют только последнюю
подтверждённую позицию, удаляемую по TTL; исполнитель не следует текущей позиции
скрытого Entity. Взгляд также использует память. Зрение учитывает LOS/FOV, приседание,
расстояние и направление взгляда. Приближение оценивается по движению игрока в
окне нескольких тиков, без принятия движения самого зверя за провокацию.

Navigation владеет moveTo/stop. Сегменты ограничены FOLLOW_RANGE, путь переиспользуется,
есть backoff, число попыток, контроль прогресса и остановка на целевой дистанции.
DRIVE_OFF ограничен количеством шагов, общей длиной, временем, паузами и stopDistance;
melee вызывается только для HUNT/ATTACK. Личность влияет на осторожность, смелость,
агрессию, слух, готовность удерживать позицию и скорость одного исполнителя.
RotationMixin ограничивает угол стандартного MoveControl параметром turnDegreesPerTick,
сохраняя сам контроллер и физику TFC. Клиентские анимации всё ещё требуют проверки.

## Интеграция с TFC

Пересоздан список действий brain; нативные сенсоры, память и расписание сохраняются.
Из native поведения остаются countdown, startSleeping, tickScheduleAndWake,
wakeFromDisturbance. Конкурирующие move/attack/territory rules заменены одним
исполнителем. У AVOID/FIGHT сохранены исходные требования PACIFIED/ATTACK_TARGET.
TFC tickAnimationStates, travel, mobInteract, food/taming и прочие методы не отменяются.
Текущая точка HOME используется только для сна, без постоянной территории.
Движение при temptation исполняется тем же владельцем, взаимодействие остаётся TFC.
NoAI/leashed/passenger/неподдержанный NBT возвращают нативный набор поведения.

Реальные ресурсы предупреждений перечислены в GAP_ANALYSIS. Для медведя
`tfc:entity.bear.attack` ссылается в assets TFC на Minecraft polar_bear.warning.
Для пантеры — cougar, для direwolf — tfc_wolf. Sons проверяет registry и пишет
`playSound_called`; это серверная проверка вызова, не прослушивание в клиенте.

TaCZ hotfix-r3 предоставляет GunFireEvent перед выполнением скрипта оружия.
Слушатель принимает только серверный неотменённый event. Попытка выстрела, которая
позднее сорвалась в скрипте, всё ещё может быть слышна; этот предел API явно указан.
Шаги/спринт/приземление идут из VanillaGameEvent; взрыв — ExplosionEvent.Detonate.
Затухание, заслоны, подавление повторов и накопление страха действуют совместно.

## Родство и сохранение

В TFC WildAnimal нет биологической ссылки на мать/отца. Принята явная модель опеки:
одна spawn cohort (тот же SpawnGroupData), либо ребёнок из offspring-from-egg.
В когорте взрослый опекун выбирается стабильно по UUID и записывается в NBT.
Соседство и одинаковый EntityType сами по себе связью не являются. Неизвестные
детёныши старого мира не усыновляются автоматически; эту границу важно проверить
на естественных спавнах пользовательского мира. Тестовые связи создаются явно.

Новый ключ `tfc_wildlife_ai.v4`, schema4. Читаются старые плоские satiety/stamina
0–100 и v3 remaster schema2 с диапазоном 0–1. Старые теги не удаляются. Будущая
неизвестная схема не перезаписывается. UUID-личность воспроизводима. Семья/родитель
сохраняются; временная встреча и её боевые цели не переживают выгрузку чанка.

## Конфигурация и trace

Каждый EntityType имеет полный независимый профиль ModConfigSpec. Семейные defaults
задаются общим шаблоном в ProfilEspece и переопределяются видом. В TOML меняется
конкретный вид. Проверяются диапазоны, целые tick/count, порядок pack join/break,
avoid/separation, размеры drive steps и границы обнаружения. Противоречие даёт
явную ошибку; стандартная коррекция NeoForge для одиночного некорректного поля логируется.
Все численные defaults нуждаются в игровой калибровке.

В alpha trace включена по умолчанию. INFO строки `[TFC-WILDLIFE-TRACE]` попадают в
latest.log: глобальный eventSequence, serverTick, mob UUID, вид, encounter, stage,
reason/source, perception, sensory checks (в том числе LOS=false), risk, proposals,
veto, решение, навигация и физическое перемещение после тика. CONFIG содержит
фактически применённый профиль; PACK/CHILD показывают смену контекста; SOUND —
ресурс и вызов; COMBAT — HP до/после и результат. Player UUID заменяется псевдонимом
в пределах запуска. Имена/адреса/токены в собственную trace не записываются.

Радиус обычной диагностики — 96 блоков, maxEventsPerTick — 2000, оба настраиваются.
Лимиты дают trace_radius_limit / DROPPED_EVENTS, а не видимость полной записи.
GameTest пишет и без игроков, чтобы проверять lifecycle. Объём активной trace велик:
в измеренном прогоне 50 животных несколько секунд дали многомегабайтный журнал.
Это режим расследования test-alpha; длительные встречи требуют места на диске.
Анализатор выдаёт whitelist CSV и Markdown, отмечает пропуски, микрооткаты,
неправильную охоту гиен, повторные маршруты и большие развороты.
